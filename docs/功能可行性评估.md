# 功能可行性评估

评估环境：2026-11-26，macOS arm64、Python 3.11.17、MetaDrive 源码 SHA `5bf8ea8909c4643a4099a250e6f5fb89c695d8b4`。以下是能力探测，不等于平台功能交付。可重载的数据集由 `src/safety_platform/sim/probe.py` 生成，见[兼容性验证](仿真器兼容性验证.md)。工作量仅为当前粗估。

| 能力 | 最小复现与结果 | 结论、后续条件与工作量 |
| --- | --- | --- |
| 暂停/恢复同一次仿真 | 在 `ScenarioEnv.reset()` 后读取 `episode_step=0`，调用 `env.stop()` 得 `in_stop=True`，再次调用后为 false，再 `step([0,0.25])` 得 `episode_step=1`。源码 `BaseEnv.step()` 在 `in_stop` 时循环等待，`stop()` 只切换进程内布尔量；未找到公开的环境状态保存/恢复接口。 | 同进程临时暂停可行；跨 worker 中断、进程重启后的精确续跑未验证。Task 6 须以持久状态收敛为终态，不能将进程内开关当作故障恢复。若要精确恢复，预计需保存/重建状态并验证确定性重放，约 3–7 天。 |
| macOS arm64 的 3D 离屏出帧 | 对 Task 1 数据集构造 `ScenarioEnv(use_render=False, image_observation=True, sensors={"rgb_camera": (RGBCamera,160,90)})`，`reset()` 抛 `Exception: Could not open window.`，Panda3D 同时输出 `Unable to open 'onscreen' window.`。本次在受限执行环境中运行；未取得 3D 图像。 | 当前环境未通过 3D 离屏探测，不能交付 3D/视频。以后在允许图形设备的目标机检查 Panda3D offscreen 配置和驱动，再测连续帧与性能；预计 2–5 天。真实 2D 俯视帧已单独通过。 |
| 外部 MetaDrive `.pkl` 可信导入 | Task 3 的本平台包包含场景、两份原生索引、规格 JSON 和清单；`verify_bundle` 只读 JSON、文件列表和 SHA-256，缺文件、篡改和越界路径在任何 pickle 读取前拒绝。独立第三方数据集没有本平台清单与规格 JSON，直接校验会拒绝；MetaDrive 格式兼容性及来源真实性仍未验证。 | Task 6 的 Web 入口只接收规格 JSON 并重建。仅受信任的本地管理命令可考虑读取已校验原生包；若将来支持外部包，需另建隔离转换流程、核验来源与版本，不能因文件哈希匹配就信任任意 pickle。预计 2–4 天。 |
| 行人横穿与更多场景类别 | Task 2 的 30 步探测可定位行人并观察到约 2.61 m 位移。Task 3 用 `create_base_scene`、`add_vehicle_track` 取得原生地图和轨迹，将轨迹类型设为 `MetaDriveType.PEDESTRIAN`，把纵向位置固定在自车前方 40 m，并以 2–5 秒平滑横向插值跨越 3.5 m 车道。`ScenarioDescription.sanity_check`、`save_dataset` 后由独立 `ScenarioEnv(reactive_traffic=False, filter_overlapping_car=False)` 重载；运行 90 步均能定位对象，实测横向位移 3.5 m。另用仅测试注册的第四类车辆场景通过通用构建器、包校验和 `ScenarioEnv` 重载。 | 原生行人轨迹能保存、重载并完成横穿；尚未实现正式行人类型的参数语义、事件检查及行人专用碰撞/TTC 验收。行人不作为首版正式模板，预计还需 3–7 天。 |
| 公开数据集导入 | 待 Task 8：选小样本核对许可、格式、磁盘与重跑成本。 | 未验证；预计 2–5 天起。 |
| MLP、图网络、碰撞分类器 | 待 Task 8/9：先量化样本数、碰撞正例和基线误差。 | 未验证；工作量取决于有效样本，不能先承诺效果。 |
| 任意自然语言新行为 | 待 Task 11：先定义新行为的语义、轨迹/控制器及原生重载验证。 | 未验证；第二阶段只解析已有模板参数。预计至少数周。 |

后续 Task 7/8/12 还需补充视频归档、磁盘成本、远期感知/照片级仿真/安全认证与多仿真器能力的评估。
