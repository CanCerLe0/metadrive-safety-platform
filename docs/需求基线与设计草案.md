# 面向安全需求的智能驾驶场景生成与评测平台

版本：设计草案 v0.13（2026-11-16；待用户确认）

依据：`任务书-刘盛东.docx`（首要依据）、`本科毕业设计（论文）开题报告-刘盛东.docx`、`20221113170_刘盛东_面向安全需求的智能驾驶场景生成与管理平台设计与实现需求分析文档.docx`。
已确定的变更：从零新建项目，以 MetaDrive 作为唯一仿真执行底座；不继承任务书指定 CARLA 与 OpenSCENARIO 的技术要求。场景保存和交换以 MetaDrive 可直接加载的原生场景数据为准。保留任务书中与仿真器和场景文件格式无关的核心业务需求。项目必须包含实际模型训练及可复现实验。

## 1. 项目目标

面向研究人员与测试人员，建立“安全需求 → 参数化场景 → 仿真运行 → 安全判定 → 证据追溯”的可复现流程。平台应能管理需求和场景、批量生成变体、运行典型危险场景、保存结果并解释每条需求由哪些测试支持。AI 能力用于在有限仿真预算内寻找更有价值的风险场景。

本项目是重新设计和实现，不以迁移旧数据库或复用旧代码为交付前提。旧仓库可作为需求与样例参考。

### 已比较的路径与选择

| 设计问题 | 路径 | 取舍 | 选择 |
|---|---|---|---|
| 项目基础 | 在旧 CARLA 仓库上改造；从零建立新项目 | 前者可复用界面与业务代码，但执行与参数体系和 CARLA 耦合；后者需重建基础功能，但模块边界可按 MetaDrive 和训练闭环设计 | 用户已选择从零建立新项目 |
| 仿真器 | MetaDrive；esmini；Apollo | MetaDrive 适合 Python 场景运行与批量实验；esmini 更偏标准场景播放；Apollo 整体集成更重 | 用户已选择 MetaDrive |
| 主要 AI 训练 | 训练风险模型以挑选场景；训练驾驶策略 | 前者直接增强场景生成与安全评测；后者将主研究对象转为驾驶算法 | 用户已选择风险模型 |

成功的最低标准是：至少一条安全需求可以追到可复现的场景版本、真实 MetaDrive 运行、原始指标、人工或规则安全判定；风险模型经过实际训练，并在同预算实验中与随机基线比较。导出的原生场景必须能在锁定的 MetaDrive 版本中重新加载、重跑。避免用页面演示代替运行证据，或用模型输出代替真实仿真结果。

### 旧材料中的差异

1. 任务书写明 CARLA 与 OpenSCENARIO；用户已明确决定新项目使用 MetaDrive 和可直接运行的原生场景格式，无须遵循这两项旧技术要求。所有生成、运行、控制和评价能力按 MetaDrive 重新设计。
2. 任务书的“主要研究内容”侧重场景生成与仿真，“预期成果”侧重仿真数据标记。新项目将两者串为同一条证据链，均纳入需求。
3. 原需求分析文档覆盖场景 CRUD、参数生成、仿真控制与导出，但没有充分覆盖任务书中的安全需求管理、场景版本、双向追溯、变更影响和安全状态标记，因此不直接作为新项目完整规格。
4. 开题报告提出 PostgreSQL、MinIO、Celery、Redis、Three.js 等实现设想；任务书并未要求这些组件。首版按实际数据量和仿真方式选择最小可运行架构。
5. 原需求文档建议使用 MD5 或普通 SHA256 保存密码；新项目若实现账户体系，应使用专用密码哈希方案，不能沿用此条技术建议。

## 3. 建议的系统边界

### 首版必须完成

- 需求、场景模板、场景实例、场景版本、运行结果和安全标记的数据管理。
- 3 类内置典型场景的参数校验、批量生成、固定随机种子复现；提供新增场景类别的注册接口，通用运行链路不得只接受这三个固定名称。
- MetaDrive 执行适配器；支持启动、停止、状态查询及历史结果。暂停/恢复应在验证 MetaDrive 的运行控制方式后决定实现细节。
- 单场景可视化运行：网页实时显示 MetaDrive 原生俯视渲染的画面，并提供运行状态、停止操作和结束后的指标入口；批量训练与实验保持无画面运行。
- 碰撞、最小 TTC、越界/车道偏离、任务完成情况等指标；每项指标记录定义和计算口径。
- 需求—场景—运行结果的双向追溯、覆盖度展示及变更后的待复验提示。
- 每个场景版本保存可编辑的参数/行为定义及 MetaDrive 原生运行产物。交付格式是 Scenario Description 场景文件（`.pkl`）和数据集索引文件；通过 MetaDrive 自带校验与 `ScenarioEnv` 重载运行验收，不保留 OpenSCENARIO 导出任务。平台的参数 JSON 仅用于编辑和版本管理，不作为对外宣称可由 MetaDrive 原生加载的文件。导出包须包含启动说明和所需版本，独立解包后可用一条项目命令调用 `ScenarioEnv` 运行。

### 场景类别扩展契约（第一版必做）

系统只内置切入、急刹和变道三类，但生成器、运行器、存储、API 和界面不得以这三个名称作为唯一可运行类型。开发者可通过 `ScenarioType` 注册接口增加新类型：提供稳定的 `template_id` 与版本、参数 JSON Schema/单位/默认值、约束校验与确定性采样、构建 MetaDrive 原生场景包的方法、预期事件检查方法及页面展示元数据。通用流程按注册表分发，未知类型返回明确错误；同一类型升级时保留旧场景版本的解释与运行能力。首版的网页表单从模板元数据生成，新增类型无需修改通用 API、运行任务或场景库代码。

扩展接口必须用一个仅在测试中注册的第四类样例证明：能够完成注册、参数校验、生成原生包、`ScenarioEnv` 重载运行、指标记录、场景版本存储、API 查询和网页表单展示。这个测试样例不构成第四类正式交付场景。新类型可以运行和评测，但只有在积累该类型的有效仿真数据并重新训练、验证模型后，才向它提供风险模型预测或模型引导搜索；自然语言入口也只解析模板目录中已有且配置了语言映射的类型。用户不能通过网页上传任意 Python 行为代码作为场景类型。

### AI 训练与实验（必做；已选路线 A）

**训练目标与结构**：训练对象是“场景风险代理模型”，不是驾驶策略。输入是仿真前可知的场景参数：模板类型、地图/车道特征、自车与目标车初始速度和间距、相对速度、切入或制动的生成参数、其他车辆数等。随机种子仅作为复现元数据，不直接喂给模型。输出是固定被测策略跑完该场景后的最小 TTC 预测值。首版用梯度提升树回归器（建议从 scikit-learn 的 HistGradientBoostingRegressor 起步），再训练 5 个按场景组重采样的模型组成集成；均值用于风险排序，模型间分歧用于选择不确定候选。另用简单的初始间距/相对速度规则作为无训练基线。只有在正例足够时才增加碰撞概率分类器，不承诺用少量碰撞样本训练可靠的分类模型。

**模型演进顺序与交付边界**：第一阶段必须完成上述梯度提升树模型的实际训练、冻结测试和场景选择实验，这是首版 AI 交付。第二阶段是有条件的研究扩展：在积累更多有效仿真样本、绘制学习曲线并确认树模型存在值得改进的误差后，使用同一组运行前场景参数训练多层感知机（MLP）回归模型。MLP 与树模型必须使用相同的数据划分、TTC 标签、测试集和搜索预算比较；只有实测更好才作为后续主模型，否则保留树模型。第三阶段仅在决定直接输入道路拓扑和多车时序轨迹时，另行研究图神经网络等结构；这需要新的数据表示与训练任务，不是首版或第二阶段的默认内容。神经网络不作为本项目首版完成的前置条件，亦不预设它一定优于树模型。

**标签定义**：每个训练样本必须来自一次真实的 `ScenarioEnv` 运行。保存每步自车与其他交通参与者的位置、速度和碰撞状态；最小 TTC 由统一的二维相对匀速外推和车体包围盒相交算法计算，在 10 秒预测窗口内截断；若已发生真实碰撞记 0，无预测相交记 10 秒。碰撞、越界和任务失败作为独立终点，不由 TTC 代替。TTC 算法、步长、窗口、车辆尺寸和场景时长须固定并版本化。仿真后的轨迹、TTC、碰撞标志不可进入模型输入，以免标签泄漏。

**主数据来源**：本项目按 3 类参数化模板做约束采样，生成 MetaDrive 原生场景包，再让同一版本的被测策略在 `ScenarioEnv` 中实际运行并自动标注。每条样本保留模板/场景版本、参数、地图、随机种子、策略与模拟器版本、原生场景包哈希、有效性状态、原始轨迹和指标。先排除初始重叠、不可达动作等无效配置；运行失败及无效样本仍留在审计记录中，不混入风险回归训练。模型最终预测的对象严格限定为“该策略在本项目 MetaDrive 配置下的结果”，不推广成真实道路事故概率。

**公开数据的作用与边界**：首选 Argoverse 2 Motion Forecasting 的小规模子集用于核对速度、间距、车道变化等参数分布，以及提供额外道路和交通轨迹样例；其官方说明有 25 万条、每条约 11 秒、包含参与者轨迹和地图（[Argoverse 2 文档](https://argoverse.github.io/user-guide/tasks/motion_forecasting.html)）。ScenarioNet 给出 Argoverse 2 到 MetaDrive Scenario Description 的转换路径（[转换文档](https://scenarionet.readthedocs.io/en/main/argoverse2.html)）。Waymo Open Motion Dataset 是备选，官方提供约 10.3 万段轨迹和地图（[Waymo 数据说明](https://waymo.com/open/data/motion/)），ScenarioNet 也有转换教程（[转换文档](https://scenarionet.readthedocs.io/en/latest/waymo.html)）。公开集记录的是原始交通行为，没有“本项目固定策略的 MetaDrive 运行结果”标签，不能直接充当主训练集；若将其转换后重跑，重跑所得样本才可加入训练，并需标记 `source=public_replay`。首版不依赖下载完整公开集；Argoverse 2 全量运动数据压缩包约 58 GB，且数据使用受 CC BY-NC-SA 4.0 限制（[下载与条款](https://www.argoverse.org/av2.html)、[许可说明](https://argoverse.github.io/user-guide/terms_and_conditions.html)）。

**采集和训练流程**：建议先生成 300 次有效初始仿真，三类模板尽量均衡；其中约 240 条训练、60 条调参。再预先生成独立的 200 条冻结测试场景，不用于采样、选模或阈值调整。之后进行 3 轮迭代，每轮在固定候选池中由模型挑选 150 条进行真实仿真，按“低预测 TTC + 高模型分歧 + 参数多样性”综合排序，结果回填并重新训练。并行保留同预算的约束随机基线：每轮也运行 150 条。建议初始研究预算约 1400 次有效运行（共享初始 300 + 模型选择 450 + 随机对照 450 + 冻结测试 200），实际预算在首轮无界面运行计时后调整并事先写入实验配置；这是实验计划，不是模型精度保证。

**划分与验收**：按基础场景族、参数区域和随机种子分组划分，近重复变体不能跨训练、验证和冻结测试；来自同一公开原始片段的变体也必须在同一分组。预测性能报告 MAE、风险阈值附近的召回情况及按模板分层的误差；场景搜索报告相同新增仿真预算下的有效风险场景数、发现成本、碰撞数和参数多样性，并给出多随机种子波动。拟以 `TTC < 1.5 秒或真实碰撞` 作为风险发现的初始口径，最终阈值须在看冻结测试结果前固定。若模型引导搜索未优于约束随机，应如实报告并检查数据量、策略敏感性和模板空间，不将公开轨迹数量当成训练成功的证据。

**被测策略**：首版使用项目内版本固定的简单规则控制器驱动自车，以保证 `ScenarioEnv` 重载后能够闭环执行；它的转向和制动规则、路线输入与参数均固定并记录。MetaDrive 官方 `ExpertPolicy` 和 `IDMPolicy` 文档注明它们仅适用于 PGMap/NodeNetwork，因此不能预设它们可直接用在由 Scenario Description 重建的地图上；若能力验证证明某种原生场景与它们兼容，可另设对照策略（[MetaDrive 官方策略文档](https://metadrive-simulator.readthedocs.io/en/latest/action.html)）。交通参与者默认轨迹回放，`reactive_traffic` 取值作为实验配置固定。

**其他扩展**：基于公开数据的轨迹预测模型和强化学习驾驶策略均留待上述闭环验收后评估，不计入首版 AI 成果。

### 单场景实时俯视画面（第一版必做）

**可行性结论**：MetaDrive 官方在 `ScenarioEnv` 示例中使用 `env.render(mode="topdown", window=False)` 获取俯视帧；该渲染器基于 2D 绘图，官方说明无需 GPU，适合 Apple 芯片上可能受 OpenGL 限制的环境（[俯视渲染文档](https://metadrive-simulator.readthedocs.io/en/latest/top_down_render.html)、[安装文档](https://metadrive-simulator.readthedocs.io/en/latest/install.html)）。因此在接口和架构层面可行。当前目标机器尚未安装 MetaDrive，锁定版本在 macOS arm64 上的连续出帧、画面内容和性能仍须在第一阶段实测；不能把文档示例当成本机验收结果。

**用户流程与范围**：用户从场景版本页选择“可视化运行”并进入该次运行的页面；页面显示道路、自车与其他车辆的实时俯视画面、运行状态和仿真时间，允许停止，结束后查看指标、轨迹与安全标记。一个页面只订阅一条运行；首版仅保证本地部署下单条可视化运行，其他批量仿真使用无渲染模式。画面是观察工具，原始轨迹与指标仍是可复验的运行证据；首版不承诺 3D 实时画面或持久视频归档。

**实现路径**：独立 worker 加载经校验的原生场景包，使用与无画面运行相同的 `ScenarioEnv`、策略、随机种子及指标算法。可视化模式调用 `env.render(mode="topdown", window=False, screen_size=(640, 360))`，按目标 5–10 帧/秒采样并编码为 JPEG；worker 原子替换本地运行目录中的最新帧，FastAPI WebSocket `/api/runs/{id}/frames` 只把该运行的新帧转发给页面，运行状态、当前仿真时间和指标沿用 HTTP API。渲染、编码和传输不得阻塞普通请求；只保留最新帧，慢客户端跳过旧帧，不在数据库保存逐帧图片。页面断线可重连，关闭页面不自动停止任务；页面保留收到的最后一帧，服务端在终态后短暂保留最新帧供重连，再按保留期限清理，异常遗留文件在 worker 重启时清理。该本地文件中转依赖 API 和 worker 共享文件系统；若以后分机部署，须替换帧中转层。

**时间与一致性**：仿真可能快于现实时间。可视化运行按仿真时间做约 1 倍速节流，保证动作可看清；批量运行不节流。画面模式不得改变场景版本、控制动作、仿真步数或最终安全指标；同一场景包、策略和种子分别以无画面与可视化方式运行，比较轨迹和指标。若渲染能力实测不足或画面为空，第一阶段保留最小复现、版本和性能记录，再调整实现，不以浏览器自绘轨迹冒充 MetaDrive 渲染画面。

**验收与交付门槛**：在目标 macOS arm64 与锁定的 MetaDrive 版本上，先用原生场景重载并连续获取至少 100 帧非空、随车辆运动而变化的俯视图，记录平均出帧时间和内存；再从网页运行切入、急刹、变道各一例，确认画面、运行 ID、仿真时间和结束状态一致。检查停止、断线重连、worker 异常与临时帧清理；核对同一场景可视化与无画面运行的轨迹和指标一致。目标 5–10 帧/秒，实测达不到时记录原因和可用帧率，不把视频流畅度伪装成仿真正确性。上述三类场景的网页实时画面未验收通过时，第一版不得标为完成；不能将静态截图、事后 GIF 或浏览器自绘轨迹替代实时 MetaDrive 画面。

### 自然语言创建模板配置（第二阶段交付）

**用户流程**：用户输入中文场景描述，例如“双车道直路，右侧车辆距自车 25 米，3 秒后切入”。系统返回识别的模板类型、参数、单位、采用的默认值、无法确定的信息和不支持的行为；用户可在保存前修改。通过校验后生成一个可预览的场景版本，调用 `ScenarioEnv` 试运行，确认指定动作实际发生，再保存为可复用的 `TemplatePreset`。预设继承基础模板的参数范围和约束，后续可以编辑参数或批量生成变体。

**实现分工**：维护只读的模板目录，列出首批 3 类模板的 `template_id`、字段、单位、默认值、范围和跨字段约束。调用 **DeepSeek API** 将自然语言解析为受限的结构化结果（模板 ID、字段值、缺失项、默认值标记、无法支持的要求）；默认使用可配置的 `deepseek-flash`，通过 Responses API 的 JSON Schema 输出约束结果（[DeepSeek 官方文档](https://api-docs.deepseek.com/api/create-response/)）。后端仍须按模板目录进行类型、单位、范围及物理约束校验，再交给确定性的 `MetaDriveScenarioBuilder` 生成原生场景包。DeepSeek 不直接生成 `.pkl`、Python 行为代码或新模板类型。本项目自训练的风险模型只用于可选的候选变体排序，不负责语言理解；该功能不要求另行训练语言模型。

**边界与失败处理**：第二阶段只支持映射到已实现的切入、急刹和变道行为。“接近自车时才切入”这类实时条件触发若当前轨迹回放模板不能表达，必须明确提示，不得改写成固定时间切入后宣称等价。缺少关键参数时要求补充；非关键参数使用默认值时须展示来源。解析成功但场景校验、重载或行为检查失败时不得保存为可运行模板。每条成功记录保存原始描述、结构化参数、基础模板及版本、大模型/提示词版本、默认值与校验记录、生成场景版本和试运行结果；外部模型不可用时保留手动配置入口。

**验收**：准备覆盖三类模板、含缺失参数与不支持语义的中文描述样本；逐条检查模板识别、参数与单位、默认值标记、错误提示、原生场景重载和指定动作出现情况。保存的预设再次调用时能修改参数并生成新场景版本。此功能是对既有模板的自然语言配置入口，不将“任意描述自动创造全新行为模板”列入交付范围。

## 4. 建议架构

前端采用 Vue 3，后端采用 FastAPI。业务核心保存可编辑的 `ScenarioSpec`，描述道路、车辆/行人、初始状态、行为触发、参数约束、随机种子和关联需求。`ScenarioRegistry` 根据类型 ID 和版本选择校验器、采样器、构建器与事件检查器；`MetaDriveScenarioBuilder` 通过该接口构建 MetaDrive 的 Scenario Description，`MetaDriveRunner` 用 `ScenarioEnv` 读取原生数据集并运行场景。API 模板目录和前端参数表单从注册元数据生成，不把通用链路限制为三类内置模板。官方格式由场景 `.pkl` 文件及 `dataset_summary.pkl`、`dataset_mapping.pkl` 索引组成，MetaDrive 提供 `save_dataset` 和 `read_scenario_data` 等工具（[Scenario Description 文档](https://metadrive-simulator.readthedocs.io/en/latest/scenario_description.html)、[官方工具代码](https://github.com/metadriverse/metadrive/blob/main/metadrive/scenario/utils.py)）。锁定具体 MetaDrive 版本，保存格式版本和生成器版本；原生格式升级时重新验证旧场景。

原生 Scenario Description 更接近道路与参与者轨迹的具体场景。首版将切入、急刹和变道等场景定义为**由参数生成的参与者轨迹**：周围车辆按轨迹回放，被测自车由固定策略驾驶；交通参与者无需根据自车的实时位置重新决策。模板中的“触发条件”在生成阶段决定动作时刻和轨迹，不承诺运行时条件触发。若能力验证显示该回放方式不能让自车策略和指标产生有效、可比较的变化，应先调整场景构建方法，再开展批量实验。后续如需根据自车状态实时切入或急刹，应另加自定义参与者策略，并单独验证其可与原生场景包一起重载运行；不能把轨迹回放称为实时交互。若使用 `reactive_traffic`，须记录其取值并检查运行结果是否符合模板预期。首个能力验证要证明“参数改动 → 原生场景文件改变 → 重新加载后的轨迹和结果相应改变”，不能仅证明文件可打开。

运行任务在独立进程中执行，避免阻塞 Web API。首版可使用 SQLite 和本地文件存储；只有在实测并发或文件规模需要时才引入 PostgreSQL、队列及对象存储。前端展示运行状态、单场景实时俯视画面、轨迹和指标，场景版本与运行证据不能被后续编辑覆盖。原生 `.pkl` 使用 Python pickle 序列化，平台默认只加载自身生成并经完整性校验的场景包；外部未知来源文件不作为普通网页上传入口。默认目标环境是当前 macOS arm64 电脑，先验证无界面运行及俯视出帧；若用户提供另一台目标机器，再调整部署与性能基线。

核心数据实体：`Requirement`、`RequirementVersion`、`ScenarioTemplate`、`TemplatePreset`、`Scenario`、`ScenarioVersion`、`RequirementScenarioLink`、`SimulationRun`、`Metric`、`SafetyLabel`、`TrainingDataset`、`RiskModelVersion`、`SearchExperiment`。训练数据与模型文件保留输入来源、版本、指标和可复现配置；`TemplatePreset` 保存自然语言描述、解析与校验记录及所依赖的基础模板版本。

## 5. 开发与验收顺序

1. **能力验证**：以“前车切入”为样例，确认 MetaDrive 能表示所需道路、参与者与行为；生成原生场景包，用 `ScenarioEnv` 重新加载并运行，保存轨迹及碰撞结果；同时验证无弹窗俯视渲染能连续输出非空、随场景变化的画面。逐项检查天气、行人、触发条件等参数的可表达性。MetaDrive 维护者指出，默认程序化交通管理器不会自动生成人和自行车；行人横穿需验证真实数据重建或自定义生成/行为策略的工作量（[官方仓库讨论](https://github.com/metadriverse/metadrive/issues/870)）。
2. **场景与原生格式**：建立 `ScenarioSpec`、场景类型注册接口、3 类必需模板和批量生成；每类场景导出 MetaDrive 原生数据集，完成格式校验与重载运行；用仅供测试的第四类样例验证通用链路能扩展，对不支持的语义给出明确错误。行人横穿只做可行性评估。
3. **业务闭环与实时画面**：实现需求、场景版本、运行记录、安全标记、追溯和变更影响；单场景网页实时俯视画面与业务界面一起交付，通过三类模板的可视化运行和至少一条需求的完整案例验收。
4. **AI 训练与实验**：固定被测策略、训练/验证/测试划分和仿真预算，训练并保存风险预测模型；比较约束随机采样与模型引导搜索，导出可复现实验报告。
5. **第一版验收与交付**：完成三类内置模板、扩展接口、业务闭环、实时俯视画面和风险模型实验后，在干净环境执行测试与真实网页端到端案例，核对 R1–R8、N2、N3 及开发期功能评估记录；通过后形成独立的第一版交付记录，再开始第二阶段。
6. **自然语言模板配置**：第一版验收后接入 DeepSeek 结构化解析；完成参数校验、用户预览、原生场景试运行和 `TemplatePreset` 保存/复用。风险模型可用于候选变体排序，但不是自然语言解析的前置条件。
7. **最终验收**：增加 N1 的端到端与异常情况验收，复核第一版功能、功能可行性评估及实测性能。旧需求文档中的响应时间和并发数是原 CARLA 方案的目标，需在 MetaDrive 原型测量后重定。

## 6. 仍需确认的产品决策

- 用户已决定不保留 CARLA 要求，MetaDrive 为新项目唯一运行底座。
- 新项目代码默认先在当前可写工作区的独立目录开发，不修改原仓库及 `Org_docs`；最终迁入其他目录时再确定目标位置。
- 用户已选择训练路线 A：训练风险预测模型并引导场景选择。被测自车先用版本固定的项目规则控制器，`ExpertPolicy` 仅在能力验证通过后作为对照策略。
- OpenSCENARIO 已从新项目交付范围删除；交付的场景格式必须通过 MetaDrive 原生加载与运行验证。
- 用户新增自然语言配置现有模板的功能，作为基础场景与风险模型闭环完成后的第二阶段交付；调用 DeepSeek API 解析描述，输出先校验、试运行，再保存为可复用的 `TemplatePreset`。
- 用户选择在单场景运行页面实时显示 MetaDrive 俯视画面；这是第一版必须完成并验收的功能，先完成锁定版本与目标机器的连续出帧验证，网页画面通过后才可宣布第一版完成。
- 用户明确第四类场景不是必做，但场景类别扩展接口是第一版必做；第一版完成后必须先独立验收，再进入 DeepSeek 自然语言功能。
- 暂不保证的功能在开发期间必须逐项评估并记录，不以可行性猜测替代验证，也不将评估结论冒充已实现功能。
